# Data Sources & Assets

Every byte of Quranic content in this app comes from a source listed here, unmodified,
with a recorded checksum and a verified licence.

---

## 1. The inviolable rule

**Never modify the Arabic Quran text.** Not by script, not by hand, not to fix an
encoding problem, not to normalise a character, not to strip a mark you believe is
wrong.

If rendered text looks incorrect, the bug is in the renderer, the font, or the
codepoint mapping — never in the source file. Fix it there.

`tool/verify_checksums.dart` runs in CI and fails the build if any Quran asset's
SHA-256 differs from `assets/CHECKSUMS.txt`. Do not update that file to make a
failing build pass without first establishing why the bytes changed.

## 3. Licence verification procedure

For each asset, before it enters the repo, record in `docs/decisions/` or
`assets/ATTRIBUTION.md`:

1. **Exact source URL and commit/version.**
2. **The licence text**, copied verbatim into `assets/licences/`.
3. **Whether redistribution in a closed app store listing is permitted.**
4. **Required attribution wording**, reproduced exactly in the app's About screen.
5. **SHA-256** of every file, in `assets/CHECKSUMS.txt`.

Where a licence is unclear or absent, **do not bundle it**. Contact the maintainer and
record the response. An unlicensed asset is a legal risk that outlives the project, and
this app is intended as sadaqah jariyah — it should not carry that.

Note: KFGQPC fonts and mushaf plate imagery generally carry usage terms that permit
free non-commercial Islamic distribution but restrict modification. Since the app is
free and never modifies the glyphs, this is expected to be fine — but expected is not
verified. Batch 0.4 verifies it.

## 4. Page images

`github.com/quran/quran.com-images` — 604 Madani-layout pages at widths 1024, 1260,
and 1920.

- **Bundle** the 1024 set. Roughly 60–90 MB, acceptable in an APK/AAB with asset packs.
- **Download on request** the 1260 and 1920 sets for high-DPI devices, into cache
  storage with no cloud-backup flag.
- Images must never be re-encoded, cropped, or colour-adjusted. Dark and sepia modes
  are achieved with a blend filter at render time, not by shipping altered images.

## 5. Coordinate databases

The `ayahinfo` SQLite databases give `x`, `y`, `width`, `height`, and `line_number` per
ayah and per word, at a specific image width. Coordinates are **resolution-specific** —
a box from the 1024 DB does not apply to a 1920 image without scaling.

Store the source width alongside the boxes and scale at render time. Getting this wrong
produces highlights that are subtly offset, which looks broken and is hard to diagnose.

Generated by `github.com/quran/ayah-detection`.

## 6. QPC glyph fonts (spike)

Per-page fonts where each Unicode Private Use Area codepoint maps to one pre-shaped
word glyph taken from the printed mushaf plates. Because no Arabic shaping occurs at
render time, Flutter's diacritic-stacking defect does not apply.

Requires, together:

- 604 font files (`QCF…`), one per page.
- A word-codepoint table: page → line → word order → codepoint.
- Line metadata to drive justification.

Distributed via the Quran Foundation's QUL utility. Verify licence in Batch 1.6 before
the spike bundles anything.

**Justification is the hard part.** Each line must fill the page width exactly, which
means rendering line-by-line with controlled stretching rather than as a paragraph.
This is what the spike must prove.

## 7. Audio

Streamed, never bundled. One reciter is 200 MB–1 GB.

- Primary: everyayah.com — per-ayah MP3, predictable URL scheme, multiple reciters
  and bitrates.
- Alternatives: Islamic Network CDN, Quran Foundation CDN.

**Before v1.0.0 release, email each host used.** These are donated-bandwidth services
run by volunteers, and shipping an app that points thousands of users at them without
asking is discourteous and risks having the endpoints blocked. Record the response in
`docs/decisions/`. Budget for cheap object storage if the app grows.

Ayah-level segment timings (needed for highlight sync) come from the Quran Foundation
recitation timing data. Word-level timings exist for some reciters and matter only if
the glyph renderer ships.

## 8. Translations

Fetched from the Quran Foundation API on user request, cached locally, never bundled.
Each translation carries its own licence and required attribution — display it in the
translation picker, not buried in About.

## 9. Attribution

`assets/ATTRIBUTION.md` is compiled into an in-app About screen. It must list every
source, its licence, and its required notice. This screen ships in Phase 0, not as
polish at the end — it is a licence obligation, not a nicety.
